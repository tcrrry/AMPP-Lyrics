# r5 聚焦恢复入口核查

用户反馈 r4 在 Apple Music 原生、QQ 与网易云三个来源都存在最后一句后回拖 / 单曲循环不聚焦；原版 Apple Music 也能出现。本次先纠正我们恢复代码不能启用的问题，不把它等同于已根治原生缺陷。

真实 7.0.0-beta / 1606 的 DEX 结构：

- PlayerLyricsViewFragment → player.fragment.e → player.fragment.l。
- player.fragment.l 实现 ia.a$c；getMediaBrowser() 返回 J4.w，是该接口的公开默认方法，类及父类没有同名声明。
- J4.w 的播放位置、是否播放、播放状态 API 继承自 J4.B。
- 原生歌词消息 Handler 是 player.fragment.l.X；y2(int) 与 message_lyrics_process_events 负责事件重排。

r4 的反射只遍历类 / 父类 getDeclaredMethod，遗漏接口，resolve 返回 null，独立时钟观察未注册。因此已有简单模拟类回归通过不能证明真实入口已接入。

r5 先用 Class.getMethod 查公开方法（覆盖继承接口），再保留原私有方法查找路径。新 Java 夹具保留真实关键继承关系，回归在 r4 实现上失败、修正后通过，覆盖采样、回退、只取消歌词消息、实际延时重排与暂停。

原包打包验证增加接口继承树、默认 getter、浏览器 API、父类 Handler、y2 及消息 ID，共 127 条扩展契约。不执行原 APK。原包映射 / DEX / 资源 / 原生库 / 签名检查继续保留。

恢复策略仍为 r4：500ms 检测实际媒体位置，显式处理当前位置；手指拖动期间不抢滚动，暂停不启动播放、旧歌曲不恢复。真实设备上的原生滚动状态、消息时序和重复播放效果尚待验证；没有新增原生设置黑屏修正。

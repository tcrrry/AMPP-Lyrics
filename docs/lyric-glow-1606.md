# 7.0.0-beta / 1606 歌词辉光规则

结论针对项目固定的 Android 原包，不推断 iOS 或其他版本。辉光由歌词时间和布局元数据触发，不分析音频；原包没有“只在句尾触发”的检查。

原包 A.V（适配符号 a0）先查当前行的前景／伴唱词块表。词块不存在，或已有主动画 o，则立即返回。特殊辉光分支要求：前景而非伴唱；词块累计时长 f 至少 1000 毫秒；累计字符数 g 不超过 7；文字不能命中 k0 或 l0 的排除类别。k0 包含中日韩、泰文、阿拉伯文、天城文，l0 包含阿拉伯文与天城文。j0 是中日文字拆分标记，参与渐变和布局计算。k0 同时含韩文。

词块的 f/g 是布局合并后的累计值，不一定等于当前字的时长／字数。若词块有同组标记 l，会收集同组绑定；已经由 N 记住的同组标记不会再次启动。已有动画、同组去重、分拆出的绑定数及布局状态都会影响实际启动，因此“长于一秒”不是充分条件。代码没有句尾判断，也没有随机数决定触发。

原生辉光有上升与回落两阶段、分绑定启动偏移。放大系数按累计时长在 1～2 秒间映射至 1～1.14；阶段时长上限 3 秒。当前 AM++ 对已验证的单个未合并 CJK 字局部放开分类，并缩短该路径过长的回落等待；长英文词限 8～32 字符、未合并、无伴唱，默认需至少 max(1500, 字符数×120) 毫秒。词尾保护与辉光触发是不同流程。

v1.4 控制（位于 Tcrrry 歌词设置）：

| 设置 | 作用 |
| --- | --- |
| 灵敏度 50%～200% | 候选门槛 = 基础门槛 × 100 / 灵敏度；普通词对应 2000～500 毫秒，长英文词保留较高基础门槛 |
| 全部长音 | 句中与句尾相同，默认保留当前门槛 |
| 仅句尾 | 只允许包含最后一个有时间且有文字内容词的词块；过滤标点与零时长词 |
| 句尾优先 | 句中候选门槛增加 50%，句尾保持原门槛 |

调高灵敏度不取消原生的语言、布局和已有动画限制。低于原生一秒门槛时，仅安全的单个未合并 CJK／英文词可局部打开特殊分支；创建后将辉光自身的阶段时长及偏移缩回真实时长比例，恢复临时元数据。在生成逐字渐变前先恢复真实时长与字符数，避免共用字数元数据影响羽化边缘；逐字扫光仍用原来的时长入参，音频、原文时间及行交接不改。异常时也恢复临时字段。

正式版本关闭测试诊断采集并移除复制入口。判定是歌词时间与词块位置，不等于识别歌声的尾音或重音。

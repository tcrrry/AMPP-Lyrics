# 首次原生设置黑屏：r2 排查记录

## 已核查的历史证据

用户的已提供诊断以歌词播放时钟、逐字事件、行切换和末字保护为主，没有首次进入原生设置时的完整系统渲染堆栈。工作区 r3～r17 日志主要是构建、打包和回归检查，不能拿来证明设备黑屏的唯一原因。

历史修补：

- 36310a0（r3）：视图创建后 requestLayout / invalidate。
- 17093aa：onViewCreated / onResume 后暂停 Fragment 玻璃捕获，设置销毁后恢复。
- 7cec426（r17）：Compose 内容方法开始前也暂停玻璃，不再以偏好模型绑定成功为暂停的前提。

这些修改没有保证暂停发生在设置 ComposeView 初始化之前，也没有保证取消绘制拦截后重新安排帧。

## 当前核实的调用路径

对固定 Apple Music 7.0.0-beta / 1606 原包检查：SettingsFragment 继承 Xb.g；Xb.g.onCreateView(LayoutInflater, ViewGroup, Bundle) 创建 ComposeView、设置 composition strategy 和内容，随后才返回视图。因此 onViewCreated 和设置内容 r1 都晚于这个初始化入口。

r2 在这个已核实的继承生命周期入口之前暂停玻璃；此时不初始化设置 ViewModel，避免首次模型创建阻塞暂停操作。原来的 Compose / Resume 路径继续保留。相同设置对象的重复进入通知幂等，避免每次重组都反复请求整个窗口布局。关闭首帧 veto 后请求下一帧；已关闭的手机玻璃回调不再重新访问材料层。直接打开自定义设置对话框也遵守暂停 / 恢复规则。

## 验证与边界

回归验证冷模型未准备、视图尚未创建时能够释放绘制 veto，重复设置通知和重叠页面关闭时机正确；译文样式与发音样式分开，发音不会再跟原文高亮。

没有连接用户设备，也没有黑屏现场的系统堆栈。这是针对已发现生命周期缺口的修正，不等于已经证明唯一根因或确认设备黑屏彻底解决。复测需强制停止后重新打开 Apple Music，再第一次进入原生设置；若仍复现，应保留该次进入前后的设备日志核对玻璃是否暂停、Compose 是否实际布局/绘制及是否有宿主异常，不能继续靠重复 invalidate 叠补丁。

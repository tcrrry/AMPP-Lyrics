# r7 突出发音逐字回退核查

用户确认 r6 的原生正文可逐字，切换突出发音后则整句亮；原生正文配 QQ 译文在设备上成功。

r6 NativeLyricsPhoneticPresentation 使用 mapped.values.all 判断整轨逐字，一条不匹配就把整个根 timing 改为 Line，丢掉其他已对齐句子的时间。改为逐句使用已对齐的原文时间；失败句仅生成自己的整句时间 span，其他句仍保留逐字。全部句子失败才整轨 Line。

原时间读取使用正则，只能读平坦 span。样式外层包装会成为非空间隙或尾部内容，从而拒绝整行。r7 使用受限的 XML 片段读取，读取实际文本节点，支持嵌套 span 和真实父 span 时间继承；未知标签、无时间文字、缺失结束时间、逆序或冲突范围均保留安全回退，解析拒绝外部实体声明且不读取外部资源。XML 解码后的完整正文用于原文辅助轨道。

已在 r6 上新增回归并观察两项失败：一句不匹配拖整轨降级、样式外层阻断内层时间。截图读音文本的日语 / wo 对齐单句测试在 r6 已通过，因此无法只凭截图断定具体哪一句导致失败。没有取得实际整曲原生 TTML，本次修复的是已复现的缺陷而非声称已确认该曲全部结构。

来源状态另有写死“突出发音 · 逐行显示”的描述，现改为随实际文档显示，并把实际对齐 / 行回退句数带入文档的 XML 注释及匹配信息。并非把显示标签改成逐字来替代时间转换。缓存目录版本推进，防止复用 r6 已拍平的突出发音文档；媒体下载数据和设置键不变。

回归包括 XML 实体、CDATA、嵌套真实时间继承、冲突范围与缺失结束时间、混合逐字 / 逐行、来源描述，以及 Android API 35 模拟环境中的离线注音完整路径。实际设备动画尚需验证。

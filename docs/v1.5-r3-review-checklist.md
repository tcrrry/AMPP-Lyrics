# v1.5-test-r3 用户意见逐项核对

范围：1.5 的来源偏好、辅助歌词、匹配交互、辉光设置及原生设置入口。公开 1.4 及四种正式下载形式保持原样；这次发布独立私人测试单 APK。下面区分代码与自动验证，以及仍需真机确认的表现，不把测试通过写成设备效果已经确认。

| 用户意见 | 本包行为与核查证据 | 验证边界 |
| --- | --- | --- |
| 质量优先按原生 AM、AM++ 作者整理库、第三方选择 | 原生存在时先保留；作者库真实接入 `am-lyrics/main/index.json`；再第三方。`NativeLyricsPreferencePolicyTest`、`AutoLyricsSourceResolverTest` | 作者库覆盖量有限，原生已命中时不会显示作者库；不是所有歌都能匹配 |
| 逐字优先也先用 AM / AM++ 已有逐字，第三方逐字权重最高 | 核查正文有效逐字时间，排除空 Word 声明；原生逐字、作者逐字、第三方逐字；同可信度档内有效逐字超过译文 / 发音完整度；较差后到结果不降级。偏好、解析、排序及升级策略回归 | 不降低歌曲身份匹配要求，错误曲目不能凭逐字胜出 |
| 原生无译文 / 发音时补齐，有条件结合 QQ / 网易云 | 原文与时间保留；正文及时间严格对齐后只补缺失辅助行，不可靠对齐不混用；再使用已配置机翻及离线注音。`CrossSourceAuxiliaryTest`、辅助来源和发音策略测试 | 不承诺任意两个版本都可混合；重复副歌、错字、时间差大时拒绝 |
| 明确区分 Apple Music 原生、AM++ 库与机翻 / 注音 | 来源菜单分开命名；按已装入指针与当前歌曲记录来源；辅助来源标记跟随具体文档，显示原生 / 库 / QQ / 网易云 / 机翻等事实。`AppliedLyricsStatusPolicyTest`、`NativeLyricsPhoneticPresentationTest`、`DesktopLyricsPresentationTest` | 未确认安装身份时保留未知，不能凭猜测显示原生 |
| 原生歌词也可突出发音 | 实际存在或补入可用发音轨道时开放切换；无发音不虚构可切换状态。`NativeLyricsPronunciationPolicyTest`、`NativeLyricsPhoneticPresentationTest` | 突出发音按已有逐行时间，不能制造不存在的音节时刻 |
| 普通发音不要跟原文一起亮 | 发音放在原生容器内上方，单独保护暗色；突出发音是用户主动选择的另一显示模式。`NativeLineLyricsPresentationTest`、发音字幕策略及布局测试 | 具体设备视觉仍需复测 |
| 译文偶尔跟原文一起亮 | 找到并修正清理时还原绑定前 alpha=1 的问题；仅还原我们改过的发音样式，保留宿主原文及译文状态，不强制 white_alpha_35。两条复用 / 切源回归在修复前失败、修复后通过 | 宿主原生动效仍由 AM 控制；不承诺所有视觉问题已消除 |
| 小于 100ms 单元平滑、英文空格及辉光 | 可选合并同句相邻非英文短单元，保留时间包络、不跨单词空格；独立空格留在 span 外。`DesktopLyricsTtmlConverterTest` 与插件 6 项兼容回归 | 选项不重置；平滑不伪造歌词时间 |
| 查看当前匹配信息正式版也保留 | 常驻入口显示播放输入以及实际装入结果的歌名、歌手、专辑、时长、平台 ID、评分；待装入候选不得冒充当前匹配。`CurrentLyricsMatchingInformationTest` | 上游没返回的字段显示未提供 |
| 重新匹配不能把最好结果逐渐排除 | “当前源选择最佳结果”清除此源跳过与手动版本并恢复最佳记录；“恢复自动选源”解除固定来源并跨源按偏好选择；只有“换一个匹配版本”排除已显示版本。历史排序、按钮状态及保留结果回归 | QQ 的设备现场失败原因尚未确认，不能据此断言限流或没有该歌 |
| 长按来源打开设置、双击不再换版本并弹页 | 单击快捷切源，长按打开独立 Tcrrry 设置；双击消费事件且不排除 / 重搜 / 打开详细页。原生菜单注册与歌曲身份保护已核对 | 单击沿用系统手势确认时间；未做设备触摸实测 |
| 切源没结果继续下一个直到找到 | 各源最多尝试一轮，首次成功停止；全部失败保留已显示歌词；切歌、再次操作或手选来源取消旧轮次。循环票据与异步刷新取消 / 拒绝队列回归 | “成功”以有效歌词解析为准；网络速度决定等待时间 |
| 辉光放在我的设置，灵敏度上限 500% | 独立 Tcrrry 页面，保存键不变；滑块、配置及真实门槛统一 50%～500%；旧 200% 保持；尾音限定仍生效；500% 短音触发时逐字扫亮仍用原时长。范围往返、Android 滑块及原生辉光作用域回归 | 500% 增加触发机会，不保证所有词都触发，也不延长歌词时间 |
| 每次使用首次打开原生设置黑屏 | 保留 r2 在 ComposeView 创建之前暂停玻璃及绘制 veto 的修正；冷模型未就绪、首帧调度及重叠页面生命周期回归 | **尚未证明彻底解决。** 已提供旧日志以歌词时钟为主，缺少黑屏现场渲染堆栈；需要强制停止后首次进入设置复测 |
| 不丢 1.4 已下载约 20GB 音频，私人发布独立包 | 外层包名 / 版本 / 签名沿用 1.4，可覆盖安装；仅升级嵌入模块；不卸载、不清数据。下载后校验外层身份、签名、嵌入版本及资产摘要；旧 release 不覆盖 | 不承诺系统允许任意降级；保留原 1.4 安装包 |

本地及 CI 全量单元测试、lint、原包接口 / 资源 / DEX / 原生库 / 签名检查见发布资产 `validation-v1.5.json` 与单 APK 的 `.validation.json`。下载后的摘要复核不能替代真机观察。此前用户明确暂缓的专辑卡住 / 上下句过渡专项本次没有继续改动。
